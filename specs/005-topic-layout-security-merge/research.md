# Research: Topic layout and security merge

Phase 0 of [plan.md](plan.md). Each entry: decision, rationale, alternatives considered. Facts about the source branches come from reading them at `origin/claude/clever-goldberg-ygio83` (13 commits, called **goldberg** below) and `origin/claude/cool-volta-rqsgdx` (36 commits, called **volta**) of `mhabedank/mobility-security-ml`, both branched from the initial commit `70d0d23`.

## R1 History import with `git filter-repo`, one source branch at a time

- **Decision**: Each source branch is cloned into a scratch repository, rewritten with `git filter-repo` (installed, `a40bce548d2c`) using an explicit path map ([contracts/path-map.md](contracts/path-map.md)): `--paths-from-file` keeps only mapped files, `--path-rename` moves them to their zoo paths, and stripped files are removed from every commit. The rewritten branch is then merged into the feature branch with `git merge --allow-unrelated-histories`, goldberg first, then volta. Code adaptation (package names, imports, lint) happens in ordinary commits after each merge, so the import commits stay pure renames.
- **Rationale**: Keeps authors, dates and messages (spec FR-006, US2 scenario 1); `git log --follow` works because each file has a single rename at import. Stripping at rewrite time is the only way to keep forbidden content (raw dataset frames, firmware images) out of a public history (R4).
- **Alternatives**: `git subtree add` (rejected: cannot strip files from old commits or map files to several target trees); one squashed import commit (rejected by the owner, decision 4); merging the unrewritten branches and moving afterwards (rejected: the forbidden files would stay in history).

## R2 Order of work

- **Decision**: (1) Move the productdev material to the topic layout and get CI green; (2) amend the constitution; (3) import goldberg; (4) import volta; (5) integrate code, packaging and CI; (6) datasets; (7) release tool for edge models; (8) register the four models and write the task documents; (9) translate and document; (10) scans and pull request; (11) retire the old repository after the merge to `main`.
- **Rationale**: The layout must exist before imports land in it (spec US1 priority). Imports before integration keep rename detection clean. Retirement last, because it is the only outward-facing irreversible step.
- **Alternatives**: Import first, restructure later (rejected: everything would move twice).

## R3 Top-level layout rule

- **Decision**: Top level holds only what is shared by all topics: `src/`, `configs/`, `zoo/`, `topics/`, `firmware/`, `hil/`, `docs/`, `scripts/`, `specs/`, `tests/`. Everything that belongs to one topic and is not importable package code or configuration lives in `topics/<topic>/`: `README.md`, `research/`, `datasets.yaml`, `reports/`, `recipes/`, plus topic-specific folders (`guideline/`, `benchmarks/`, `spike/`, `deploy/`, `scripts/` for productdev). The full map is in [contracts/path-map.md](contracts/path-map.md).
- **Rationale**: One rule a contributor can apply without asking (SC-002); productdev's top-level clutter (`guideline/`, `reports/`, `benchmarks/`, `spike/`, `deploy/`, `docs/recipes/`, `scripts/{pilot,span,railway,spark}`) all follows it.
- **Alternatives**: Keep `scripts/` per kind at the top level (rejected: half of the scripts belong to one task); topic-first including code (`topics/<topic>/src`) (rejected: breaks the single Python package and the published import path `mobility_model_zoo.productdev.jtbd.span`).

## R4 What is not imported

- **Decision**: Stripped from history at import (never in the zoo):
  - goldberg `models/can-ids-tiny/c/generated/test_vectors.h` and `prebuilt/*.bin`: they embed 4,000 raw frames of can-train-and-test. The zoo repository is public and the constitution forbids publishing datasets (VI, IX).
  - goldberg `c/generated/can_ids_tiny_model.h` (2.6 MB, generated by emlearn), `results/model.joblib` (pickle), `results/logs/`, `uv.lock`, `.gitignore`, `LICENSE`, `pyproject.toml` (their content is merged by hand).
  - volta `firmware/lib/modelzoo/src/model_zoo.{c,h}` (generated, 402 KB, rewritten by every training commit), `models/zoo/*` (weights, eval sets, manifest), `models/train-request.json`, `models/hub-release.json`, `hilbench/hub.py`, `.github/workflows/{hub,train}.yml`, `LICENSE`, `.gitignore`, `pyproject.toml`.
  - `publish.py` of goldberg (its own Hugging Face upload).
- **Rationale**: FR-011 and FR-013. Everything stripped is either regenerable (headers, firmware, zoo sources), a release artifact that belongs in staging (weights), forbidden (raw frames, dataset mirroring) or replaced by the zoo's version (packaging files). The old repository stays readable (archived), so nothing is lost.
- **Consequence**: The trained weights of `can_ids_road`, `mimii_fan_ae`, `har_cnn1d` and `can-ids-tiny` are not in the zoo. Publishing any of them requires a retraining run from a zoo commit anyway (gate rule 8 needs the recipe at a zoo commit). This feature only makes the models releasable (spec), so the gate reports "files not staged" for them (SC-004).
- **Alternatives**: Keep the weights in git (rejected: binary churn, and rule 8 cannot use them); copy them into private staging repos now (rejected: they could not pass rule 8 and would be replaced at retraining).

## R5 Package names; `datasets`, not `data`

- **Decision**: New subpackages under `src/mobility_model_zoo/`:
  - `datasets/`: dataset declarations loader, downloader, license check (from volta `hilbench/data/`).
  - `edge/`: shared edge code. `edge/int8/` (QModel, quantisation, bit-exact reference, float net, codegen, TFLite import; from volta `hilbench/ml/`), `edge/bench/` (HIL bench: config, discovery, build, flash, transport, device, session, lock, power, QEMU, results, pytest plugin, CLI, synthetic reference models; from volta `hilbench/`).
  - `security/can_ids/`: CAN intrusion detection (goldberg `src/msml`, `pipeline.py`; volta CAN part of `train_real.py`).
  - `condition_monitoring/sound_anomaly/` and `condition_monitoring/activity/`: MIMII and HAR parts of `train_real.py`; log-mel features from `hilbench/ml/features.py`.
- **Rationale**: The zoo's `.gitignore` has an unanchored `data/` and `zoo history-check` forbids a directory named `data` at any depth (`history.py:18`). A package called `data` would be ignored by git and fail the history check. Python identifiers cannot contain a hyphen, so the topic `condition-monitoring` maps to `condition_monitoring`.
- **Alternatives**: Anchor the ignore and relax the history check (rejected: weakens a safety check to save a name).

## R6 Topic ids and the schema pattern

- **Decision**: Topic ids `security` and `condition-monitoring`. The pattern in `topics.schema.json` and `model.schema.json` widens from `^[a-z][a-z0-9]{1,15}$` to `^[a-z][a-z0-9]*(-[a-z0-9]+)*$` with `maxLength: 24`. `hf_collection` stays `null` until the first publication in the topic; `zoo publish` already creates the collection reference only through the owner.
- **Rationale**: Owner decision 2; hyphenated ids read well as Hugging Face tags. Existing ids still match.
- **Alternatives**: `condmon` (rejected: unclear as a public tag).

## R7 Model names

- **Decision** (working names, final at first publication; names never change after it):

  | Old name | Zoo name | Topic | Task | Why the name |
  |---|---|---|---|---|
  | `can-ids-tiny` (goldberg) | `canary-forest` | security | `can-ids` | canary = early warning on the CAN bus; variant = random forest |
  | `can_ids_road` (volta) | `canary-mlp` | security | `can-ids` | same family, int8 MLP |
  | `mimii_fan_ae` (volta) | `murmur-fan` | condition-monitoring | `sound-anomaly` | murmur = abnormal sound; variant = machine type |
  | `har_cnn1d` (volta) | `pace-cnn` | condition-monitoring | `activity` | pace = movement; variant = 1D CNN |

  Synthetic bench references (`can_ids_mlp`, `sensor_ae`, `imu_gnss_cnn1d`) stay fixtures of `edge/bench`, are regenerated deterministically by `edge.bench.reference_models`, and are never zoo models (US2 scenario 5).
- **Rationale**: `<name>-<variant>` rule; one family per task where several variants compete (two CAN detectors share `canary`). C symbols, `MI_EXCLUDE_<NAME>` macros and protocol names use a sanitised form (`canary_mlp`), done in `edge.int8.codegen`.
- **Alternatives**: Keep descriptive names (`can-ids-road`) (rejected: the dataset is not the variant, and the rule asks for a family name).

## R8 One evaluation protocol per new task

- **Decision**:
  - `can-ids`: a common frame format (`ts_us, can_id, dlc, b0..b7, label, capture, vehicle`) for both can-train-and-test and ROAD; frame metrics (precision, recall, F1, FPR, AUC-PR) and event metrics (episode recall, time to alarm, false alarms per hour) from goldberg `eval/metrics.py`; splits: goldberg's four-way unseen vehicle × unseen attack on can-train-and-test, plus ROAD held-out captures (volta: attacks ending `_2`, ambient by name hash). Both `canary-*` models are scored on both test sets with the same code (Principle VIII). Benchmark name `can-ids-v1`, frozen at first use.
  - `sound-anomaly`: clip AUC and pAUC per machine id on held-out MIMII 6 dB fan clips (volta protocol). Benchmark `mimii-fan-v1`.
  - `activity`: accuracy and macro-F1 on the official UCI HAR test split (30 % of subjects, unseen). Benchmark `uci-har-v1`.
  - The int8 result on the bit-exact reference is the reported result; float results are informative only.
- **Rationale**: FR-009 and Principle III (measure before optimising); ground truth exists, so frontier consensus is not the reference (R12). Running the cross-dataset CAN evaluation is the first step of the feature that releases a `canary` model, not of this one.
- **Alternatives**: Evaluate each CAN model only on its own dataset (rejected: not comparable, Principle VIII).

## R9 Overlapping code (FR-010)

- **Decision**:

  | Concern | goldberg | volta | Kept |
  |---|---|---|---|
  | Dataset download and registry | `can_train_and_test.py` (Bitbucket API, CSV → Parquet) | `data/registry.py`, `download.py` (Zenodo, UCI, range reads, `SOURCE.json`) | volta's downloader as shared `datasets`; can-train-and-test becomes a declaration plus a provider adapter for Bitbucket; its CSV parsing moves into `security/can_ids/frames.py` with the ROAD candump parser (common frame format, R8) |
  | Metrics and evaluation protocol | `eval/metrics.py` (frame and event metrics) | inline metrics in `train_real.py` | goldberg's, used by both CAN models |
  | CAN features | C streaming extractor (13 features, used via ctypes and on the MCU) | Python per-frame features (32 features) | both, as model-specific feature definitions of `canary-forest` and `canary-mlp`; they are model inputs, not a duplicated concern |
  | Export to C | emlearn random forest with float32-exact thresholds | int8 engine `microinfer` with bit-exact reference | both: one for tree models, one for neural nets; documented in the `can-ids` task document |
  | Device benchmark | ESP-IDF replay firmware, QEMU only | HIL bench (sim, QEMU, real boards, 11 targets) | the HIL bench is the measurement path; the ESP-IDF firmware is kept as the `canary-forest` device build and gets a bench protocol adapter later (task in the release feature) |
  | Cloud setup | `scripts/setup-cloud.sh` (ESP-IDF, QEMU, Arduino) | `hil/setup-host.sh` (udev, groups) | both: different purposes (toolchains vs. bench host) |

  The research log (`topics/security/research/merge-log.md`) records every dropped file and reason (SC-001).
- **Rationale**: Keep what is unique (event metrics, alarm stage, streaming features, int8 engine, bench); drop what is duplicated or forbidden.

## R10 Dataset declarations replace the Python registry

- **Decision**: `topics/<topic>/datasets.yaml` holds the declarations (fields in [data-model.md](data-model.md)); `mobility_model_zoo.datasets` loads all topic files and validates them against `datasets.schema.json`. Data goes to `$MMZ_DATA` (default `~/.cache/mobility-model-zoo/datasets/<id>/`), never into the repository; `SOURCE.json` is written next to the data as in volta. Providers: `zenodo`, `uci`, `bitbucket`, `url`. License check: Zenodo and UCI through their APIs; providers without a machine-readable license get `license_check: manual` with a date and a link, and `zoo data verify` reports them as `manual`, never silently `ok`. `can-mirgu` stays with status `broken_at_source`. Rejected datasets are declared with status `rejected` and a reason.
- **Training guard**: every training entry point calls `datasets.require_training_allowed(id)`, which refuses `benchmark_only`, `rejected` and `broken_at_source` entries (FR-017).
- **Rationale**: FR-014 to FR-017; declarations are reviewable data, readable per topic (US3).
- **Alternatives**: Keep the Python dataclass registry (rejected: not per topic, not readable by non-developers).

## R12 Constitution amendment 1.5.0 (MINOR)

- **Decision**: Amend, with rationale and version bump:
  - **Scope note**: Principles I, II, VII, X and the agreement pilot (IV) apply to tasks whose reference is model labeling (today JTBD); tasks with a ground-truth dataset name the dataset labels as their reference.
  - **III**: For ground-truth tasks, results are measured against dataset labels and may be called accuracy; the frontier-consensus wording stays for model-labeled tasks.
  - **V**: Budgets per runtime class. Python models state RAM in GB and CPU/GPU; microcontroller models state flash and RAM in KB and a named target board; device measurements must say whether they come from a real board, an emulator or a simulator.
  - **VI**: Dataset declarations per topic with license, permitted use, commercial use and retention; the model license must respect share-alike terms of its training data; non-commercial data is `benchmark_only`.
  - **VIII**: Ludwig is the default for text models; each task chooses its framework in its first spec and justifies it.
  - **IX**: Raw labels retention applies to model-labeled tasks.
  - **Resources**: inventory adds CI runners (simulated and emulated boards) and the bench boards; cost order unchanged.
  - **Project Scope**: the topic layout (R3) and "one topic, one collection, one `topics/<topic>/` folder".
  - **Quality gates**: "gate before reporting a result" lists consensus, contested items and Pareto front only for model-labeled tasks; ground-truth tasks need the frozen protocol (R8) and the int8 result.
- **Rationale**: FR-026. The existing scope note (constitution lines 35–41) already limits several principles to JTBD; the amendment makes the remaining JTBD assumptions explicit instead of violating them silently.
- **Alternatives**: Record deviations per model (rejected: every edge model would repeat the same deviations).

## R13 Release tool for edge models

- **Decision**: Additive changes; published records stay valid:
  - `model.schema.json`: new optional `runtime` (`python` default, `mcu`); `languages` may be empty when `runtime: mcu`; `base_model`/`base_model_license` may both be null outside the sandbox (trained from scratch, stated on the card); `how_to_run` for `mcu` needs `{repo_id}` and `{revision}` but not `{text}`; new optional `card.device_usage` (C snippet); figure path pattern `^(docs|topics)/…`.
  - `release-record.schema.json`: `performance.budget` becomes one of `{ram_gb, gpu}` or `{ram_kb, flash_kb, target}`; `provenance.sources[]` gets optional `dataset` (id of a declaration); `evaluation.reference_kind` (`model_consensus` default, `ground_truth`).
  - `results.schema.json`: performance metrics get optional `origin` (`real_board`, `emulator`, `simulator`, `host`), required for `mcu` by the gate.
  - Gate: rule 6 also checks dataset licenses against declarations and share-alike compatibility; rule 10 uses the ground-truth sentence instead of the agreement sentence when `reference_kind: ground_truth` and then allows "accuracy"; rules 12/13 for `mcu` run the host reference on `examples/*.json` (input vector → expected output, bit-exact) instead of the Python snippet; new rule 15 "device evidence": `mcu` models need flash and RAM metrics and, unless `experimental`, at least one `real_board` latency.
  - Card template: per-runtime "How to run" (Python host reference plus C usage), speed line in KB with target and origin column, provenance text for third-party datasets.
  - Schema copies: the canonical contract copies move from `specs/003-…/contracts/` to `specs/005-…/contracts/`; `tests/release/test_schemas.py` points at the new location.
  - Details: [contracts/release-format.md](contracts/release-format.md).
- **Rationale**: FR-019 to FR-021; spec US4.
- **Alternatives**: A separate release path for edge models (rejected: owner decision 1, constitution "Tasks and Releases").

## R14 Moving productdev without breaking published versions

- **Decision**:
  - Published release records `scout-large/releases/0.1.{0,1}.yaml` are not edited; rule 8 reads their recipe files at the recorded commit through git, and `zoo audit` reads only tags and card hashes.
  - `zoo/models/scout-large/model.yaml` figure paths move to `topics/productdev/recipes/figures/…`.
  - `zoo deprecate` and any re-render of a published version read `model.yaml` at that version's git tag (`<model>/v<version>`), so figure URLs keep pointing at files that exist at that tag.
  - Configs, scripts, tests and `span/results.py` defaults follow the new paths; `freeze` hashes are content-based and do not change.
- **Rationale**: FR-004; the move must not change any frozen hash or published URL.

## R15 Tests and pytest plugin

- **Decision**: Tests move to `tests/{datasets,edge,security,condition_monitoring}/`; HIL suites to `tests/edge/hil/`, marked `hil` and deselected by default (`addopts` gets `-m 'not slow and not hil'`); CI runs them explicitly against the simulator and QEMU. The bench plugin is loaded with `-p mobility_model_zoo.edge.bench.pytest_plugin` and only acts on tests that request `dut`. Synthetic eval sets are generated in fixtures, not committed.
- **Rationale**: The existing suite (363 passed, 1 skipped, about 143 s offline) must stay green and fast; HIL tests need a compiler and a board.

## R16 Dependencies and extras

- **Decision**: New extras: `edge` (numpy, pyserial, pyyaml, jsonschema), `edge-hw` (esptool, platformio, pytest-xdist), `edge-train` (tensorflow-cpu, tflite, ai-edge-litert, scikit-learn, emlearn, setuptools, pandas, pyarrow). Python stays 3.12 with `uv`. CI installs `--extra jtbd --extra release --extra edge` (no TensorFlow). Ruff config of the zoo applies to imported code (line length 105, E/F/I/B/UP); firmware SCons scripts are excluded.
- **Rationale**: Keep the base install unchanged for `scout-large` users; keep CI time bounded.

## R17 CI and credentials

- **Decision**:
  - `ci.yml`: existing `test` job plus `edge-sim` (native simulator HIL suite) and `edge-qemu` (ESP32 in Espressif QEMU), and a `firmware` matrix over the 11 bench targets plus the `canary-forest` ESP-IDF build, the latter two only when `firmware/`, `hil/` or `src/mobility_model_zoo/edge/` change (paths filter in a separate workflow `firmware.yml`).
  - `datasets.yml`: weekly and on changes of `topics/*/datasets.yaml`; runs `zoo data verify`; no data downloads in CI.
  - `hil.yml`: self-hosted real boards; runs only when the repository variable `HIL_RUNNER_ENABLED` is `true`, otherwise the job is skipped (US4 scenario 4).
  - volta `train.yml` is not adopted: it committed weights back to the branch, which conflicts with R4 and rule 8. Training runs locally (Mac or DGX Spark) and artifacts go to staging with `zoo stage`.
  - Secrets: workflows reference only `HF_RELEASE_TOKEN` (exists). `HF_STAGING_TOKEN` is used locally by `zoo stage` from `.env`, not in CI. New repository variable `HIL_RUNNER_ENABLED`. Documented in `docs/credentials.md`.
  - Secret scan: `zoo history-check` (gitleaks plus forbidden paths) over the merged history before the pull request (FR-023); CI keeps running it.
- **Alternatives**: Run firmware builds on every push (rejected: 11 cold builds of 3–10 minutes each).

## R18 Retiring the old repository

- **Decision**: After the pull request is merged into the zoo's `main`: commit a README to the old `main` that points to the zoo and lists where each part went; delete the old secrets `HF_RELEASE_TOKEN` and `HF_STAGING_TOKEN` and any variables; archive the repository with `gh repo archive`. The `claude/*` branches stay. Private Hugging Face repositories created by the old `hub` workflow (`hilbench-*`, in the org of the old `HF_STAGING_ORG` variable or the token owner) are listed for the owner, not deleted (FR-025). If the old tokens are distinct from the zoo's, the owner revokes them on Hugging Face; deleting a GitHub secret does not revoke a token.
- **Rationale**: FR-024; owner decision 4.
