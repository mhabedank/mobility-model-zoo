# Contract: model card (Hugging Face `README.md`)

The card is generated by `zoo build` from `model.yaml`, all release records of the model, the results files and the example outputs. Nobody edits it by hand. The sections below are mandatory and appear in this order (FR-010). `zoo validate` fails if one is missing or empty.

## Front matter (machine-readable metadata)

```yaml
---
license: apache-2.0                  # from model.yaml license (lowercased Hub id)
language: [de, en]                   # model.yaml languages
library_name: pytorch                # model.yaml library_name (set explicitly)
pipeline_tag: token-classification   # model.yaml pipeline_tag
base_model: FacebookAI/xlm-roberta-large
tags: [mobility, productdev, jtbd, mobility-model-zoo, experimental]
model-index:
  - name: <model name>
    results:
      - task: {type: token-classification, name: <task title>}
        dataset: {type: <benchmark id>, name: <benchmark id> (frozen), split: <split>}
        metrics:
          - {type: <metric name>, value: <value>, name: <description>}
---
```

The status (`experimental`, `released`, `deprecated`) is always a tag, so the Hub can filter by it.

## Body sections

1. **Title and status banner**: model title, version, date and a status box. For `experimental`: "Experimental: the output format may change in a minor version before 1.0.0." For `deprecated`: the reason and the successor.
2. **Summary**: `model.yaml summary`, topic (linked to the collection) and task.
3. **Intended use** and **Out-of-scope use**.
4. **Input and output**: format description and one example output.
5. **How to run it**: the install line with the real tag, then `card.how_to_run`. A note on pinning `revision="<commit>"` for strict reproducibility.
6. **Examples**: three example texts and the model's actual output for each, produced by the gate.
7. **Quality**: a table with metric, value, what it measures, reference, benchmark (frozen version), number of items and date. Above the table, always: "These numbers are agreement with <reference>; they are not measured against human ground truth."
8. **Speed and memory**: a table from `performance.json` with the hardware named in every row, plus the memory and hardware budget.
9. **Limitations and risks**: `card.limitations`.
10. **Training data provenance**: the source groups (origin, license, permitted use, count) and the teachers with their license basis. A sentence that the training data is not published and why (constitution Principle VI).
11. **Training recipe**: link to `recipe.doc` and `recipe.config` at `recipe.git_commit` on GitHub.
12. **Version history**: one row per published version: version, date, status, change type, changes, and the main quality metrics side by side (US4).
13. **License**: the license and, for an exception, its reason.
14. **Citation**: `card.citation`.
15. **About the zoo**: one line linking the organization, the topic collection and the repository.

## Rules

- Every number comes from a results file (FR-016). The template has no literal numbers.
- No metric, heading or sentence calls a quality number "accuracy" (FR-014).
- The card contains no training text, no labeling output and no link to `data/`.
